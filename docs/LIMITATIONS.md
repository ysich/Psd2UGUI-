# 已知限制

> 这一页存在的意义是「让你在踩坑之前就知道有坑」，以及「遇到问题时能判断是 bug 还是本来就做不到」。
> 凡是本页写到的限制，实现里都会**给一条诊断**，不会静默出错——出问题先看 `.report.json` 里的 `diagnostics`。

## 1. 定位限制

| 不做 | 说明 |
| --- | --- |
| 运行时加载 PSD | 只在编辑器里跑，产物是 Prefab 与 PNG。打包出来的游戏里没有 PSD 解析器 |
| Photoshop 侧面板 | 只有 Unity 侧。美术改完 PSD 回 Unity 重导 |
| 云端 / AI 识别 | 只留了 `ITypeInferrer` 接口与本地启发式规则，不外联任何服务 |
| 像素级 1:1 还原 | 目标是「省掉手工拼界面」，不是「和设计稿逐像素一致」 |

## 2. 解析能力

### 支持

| 项 | 情况 |
| --- | --- |
| 格式 | PSD 与 PSB（大文件），版本 1 |
| 位深 | 1 / 8 / 16 / 32 位 |
| 颜色模式 | RGB、灰度、位图；CMYK 做近似转换；索引色按 RGB 通道处理（这两种会给警告） |
| 通道压缩 | 原始、RLE、ZIP、ZIP + 差分预测 |
| 图层 | 图层组（含折叠状态）、图层蒙版、图层不透明度、裁剪图层、图层 ID |
| 文本 | 内容、字号、颜色、字体名、对齐、行距、字距、是否段落文本 |
| 图层效果 | 投影 / 内阴影 / 外发光 / 内发光 / 斜面和浮雕 / 颜色叠加 / 渐变叠加 / 描边 / 缎面 / 图案叠加 |

### 不支持或会降级

| 项 | 表现 |
| --- | --- |
| **图层混合模式** | 只有普通的 alpha 合成。`Multiply` / `Screen` / `Overlay` 等模式会被忽略——叠出来的颜色会和 PS 里不一样。这是当前最大的还原度缺口 |
| 图层组的混合模式与组不透明度 | 同上，不参与合成 |
| 调整层（色阶、曲线、色相/饱和度…） | 不应用。PSD 里带调整层时，渲染结果会偏 |
| 智能对象 | 只使用 PSD 里嵌的**预览像素**（即图层自身的光栅数据），分辨率可能低于原始素材；里面的内容不会被递归解析 |
| 矢量蒙版 / 路径 | 只用光栅化后的像素结果 |
| 剪贴蒙版链 | 只处理一层裁剪关系（`clipping` 标志），多层嵌套会退化 |
| 未识别的图层效果类 | 记一条警告（`未支持的效果类`），该效果不生效 |
| 索引色调色板 | 不读调色板，按 RGB 通道处理，颜色会错 |
| 文本引擎数据缺失的老 PSD | 内容可能拿到，但字号与字体缺失，会给警告 |

## 3. 还原到 uGUI 时的差距

| 项 | 说明 |
| --- | --- |
| 字体 | 必须在工程里有**同名字体**资产，否则报 `preflight.font-missing` 并用默认字体。字号按像素直传 |
| 文本排版 | 行距 / 字距按比例映射，TMP 与 PS 的断行规则不同，长段落可能出现换行位置差异 |
| 文本渐变 | 只支持上下两色的近似；多色标 / 角度渐变会报 `text.gradient-unsupported` 并退化成单色 |
| 部分文本效果 | TMP 覆盖不到的效果报 `text.effect-unsupported`，退化成不带该效果的文本 |
| 圆角 / 矢量形状 | 变成一张位图，缩放会糊。要真九宫请在图层名里写 `sliced` |
| 九宫检测 | 只在这张图**确实存在可利用的边框区域**时才给边框；检测不出就按整图导（不会瞎切） |
| 复杂控件的子结构 | Slider / ScrollView / Dropdown / Toggle 等会按 uGUI 的标准结构补齐缺的零件（并报 `prefab.*` 诊断），补齐的零件是「能跑」的样子，不是「和设计稿一模一样」 |
| 根节点 | 默认挂 Canvas + CanvasScaler + GraphicRaycaster，方便直接拖进场景看。参考分辨率默认取 PSD 画布尺寸 |

## 4. 工程与流程

| 项 | 说明 |
| --- | --- |
| 产物必须在 `Assets/` 下 | `AssetRoot` 指到工程外会直接报 `resource.outside-assets` 错误 |
| 批处理只扫 `*.psd` | `-psd2ugui-psdDir` 不会收集 `.psb`，`.psb` 只能单个指定 |
| 手改受管属性会被覆盖 | 位置、尺寸、图片、文本、颜色、九宫这几类是工具管的，重新导出会被设计稿覆盖。要保住就删掉节点上的 `Psd2UguiNode`，或改用覆盖表 |
| 关掉「标出节点来源图层」等于关掉增量 | 认不出哪些是自己生成的，行为会退化 |
| 贴图不压缩 | 默认 UI 图不压缩（避免色带），图集大时包体会变大，可在项目侧改 |
| TMP 需要自己装 | 装了 `com.unity.textmeshpro` 并有 Essentials 才会走 TMP；否则降级到 UGUI `Text` |
| 一个 PSD 一个模块 | 模块名是整体选项，不能让一个 PSD 里的不同图层落到不同模块 |

## 5. 性能

参考数据（750 × 1334、65 个图层、12 张导出图的真实设计稿，解析 + 计划）：

```text
parseMs ≈ 20 ms
planMs  ≈ 12 ms
totalMs ≈ 33 ms
```

解析是**按需解码**的：只有真的要导出像素的图层才会解通道数据并合成位图，
所以图层数多但大部分是分组时，耗时不会线性上涨。

已知的瓶颈位置：

- 超大画布 + 很多图层的 RLE 解码；
- 首次导出要写 PNG 并让 Unity 重新导入，这一段的耗时主要在 Unity 侧，不在本插件里。

## 6. 仓库本身的现状

| 项 | 说明 |
| --- | --- |
| 仓库里没有 `.meta` 文件 | 别人 clone 后 Unity 会自己补。作为 UPM 包分发时这不规范，发版前应补上（见 [TASKS.md](TASKS.md) 的「已知遗留」） |
| 真实 PSD 冒烟依赖本机样本 | 样本有体积与授权问题不入库；需要时用 `PSD2UGUI_SMOKE_PSD=<样本.psd> Tools~/dev-project.sh` |
| TMP 分支未在真实 TMP 工程验证 | 宿主工程没导 TMP Essentials，走的是降级路径 |
| 版本 | `0.1.0`，接口可能变 |

## 7. 遇到问题怎么报

带上这三样，基本就能定位：

1. `.report.json`（`Assets/<AssetRoot>/report/<模块>/` 下）；
2. `.contract.json`（同一层目录，`contract/` 下）；
3. 出问题的那个图层在 PSD 里的**图层路径**（报告里的 `layerPath` 就是它）。

`report.json` 里的每一条诊断都带 `code` 与图层路径，格式见 [契约文档](CONTRACT.md#6-diagnostics)。
